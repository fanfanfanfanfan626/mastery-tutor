# Mastery Tutor repository instructions

## Product identity

This repository is a host-neutral, two-Skill teaching system. The only canonical Skill sources are:

- `skills/mastery-coach`
- `skills/mastery-tool-creator`

They are one product and must be installed together. There is intentionally no root `SKILL.md`.
Generated host packages are adapters, not additional sources of truth.

## One-prompt installation

When a user gives an AI this repository and asks to install it, read `AI_INSTALL.md` first. Detect
the current host and follow the linked host-specific instructions. Do not describe a clone, package
preflight, or partial Skill copy as a successful installation.

For Codex, read `docs/install/codex.md`, keep the repository or Release in a stable path, run the
root installer. The default registers a marketplace for desktop Plugins Directory installation.
`registered-awaiting-ui-install` is action required, not success. Require `codex plugin list --marketplace mastery-tutor`
to report `mastery-tutor@mastery-tutor` installed and enabled before claiming success. The compatibility `plugin add` path requires explicit opt-in and a runtime help probe. Never automatically replace a conflicting marketplace source. Do not use `skill-installer` for the Codex
adapter. If an old `mastery-learning` plugin or standalone Skill copy is found, show the exact
conflict and follow `MIGRATION.md`; never delete learner files or legacy installs silently.

For other Agent Skills hosts, use `install-agent-skills.py` and the matching document under
`docs/install/`. File installation proves packaging only. Do not upgrade a host to Verified until
the complete matrix in `COMPATIBILITY.md` has passed on a named host version.

## Generated adapters

`adapters/codex/` contains Codex-specific manifest and asset sources. The checked-in marketplace
under `.agents/` and plugin under `plugins/mastery-tutor/` are generated by:

```text
python quality/build_adapters.py --write
```

Never edit generated adapter files directly. After changing canonical Skills or adapter sources,
regenerate and run `python quality/build_adapters.py --check`. CI must reject any source/package
drift. Do not use symlinks or junctions in adapter packages or release archives.

## Repository changes

- Read `VERSION` as the only release version source; do not hardcode it in manifests, archive names,
  evaluation paths, or workflows.
- Preserve `.mastery/` learner workspaces and compatibility with existing registry locations.
- Keep core terminology host-neutral. Codex-specific commands and task terminology belong only in
  the Codex adapter and its installation documentation.
- Capability limitations may narrow features, but must never weaken evidence, privacy, source,
  answer-leakage, inspection, cleanup, or deletion boundaries.
- A platform claim must follow evidence. “Core-compatible,” “Experimental,” and “Verified” are
  distinct statuses defined in `COMPATIBILITY.md`.
